# 设备同步与通用协议

同步支持两个独立入口，共用 `SyncData` 数据格式和本机备份/替换逻辑：

| 方式 | 账号 | 后台服务器 | 条件 |
| --- | --- | --- | --- |
| 设备直接同步 | 不需要 | 不需要 | 局域网 IPv4 互通，两个设备同时在线 |
| 服务器同步 | 需要 | 自己或他人部署 | 能连接服务器，不要求设备同时在线 |

当前客户端为 Windows WPF，手机端后续开发。共享协议不引用 WPF，不强制依赖账号。首版是手动、整份快照同步，不逐条合并。

## 两台电脑直连

1. 两台电脑连接同一局域网，例如同一 Wi-Fi、有线网络或手机热点。
2. A 打开“设置 → 设备、账号与数据同步 → 设备直接同步（无需账号）”。
3. A 选择 B 可访问的本机网卡地址和空闲端口，点击“开启接收”。
4. 把完整 `sn1:` 配对码通过可信方式交给 B。持有码者在有效期内可读取同步内容，不应公开发布。
5. B 在相同窗口粘贴配对码，点击“连接并选择同步方向”。发送本机数据、接收对方数据或取消，都会明确提示。
6. B 发送时，A 还需确认接收；B 下载时，B 自己确认。替换前会备份接收端本机原文件。
7. 完成后 A 点击“停止接收”或关闭设备直连窗口。配对码最长 10 分钟有效，到期自动停止；再次开启会生成新密钥和证书。

不需要另行启动 Server 或 Docker，不会上传到后台。同步便签、清单、子任务、完成状态和每张卡片的样式。窗口位置、开关、全局设置与背景图片文件保留本机。

Windows 防火墙提示时请允许专用网络访问；应用不会自动修改规则。`127.0.0.1` 仅用于本机测试。多网卡时应选择两台电脑相通的地址；端口占用时可改为 1024–65535 内的空闲端口。访客 Wi-Fi 或热点的设备隔离可能阻止互访。

当前没有蓝牙、USB、扫码、IPv6、自动发现、离线队列、跨公网 NAT 穿透和中继。不同网络下可使用 HTTPS 服务器同步。等待接收确认约一分钟会超时；未收到确认时，对方可能已保存而响应丢失，应重新读取，不能视为已经回滚。

## 传输接口

`ISyncTransport.ReadAsync()` 返回 `{version,data}`；`WriteAsync(data,expectedVersion)` 在目标版本仍匹配时替换快照。版本是目标设备生成的**不透明字符串**，调用方原样传回，无需跨语言重算 JSON 摘要。

服务器把 SQLite 递增版本映射为字符串，当前 Windows 设备接收端使用内容摘要。接收端必须在确认前后检查预期版本，并保证检查和提交之间不发生并发写入。WPF 在 UI 线程完成此过程；手机端也需实现同等事务保护。备份或写盘失败时不切换内存数据。

## 局域网协议 v1

TCP + TLS 1.2/1.3，一次连接一个请求和响应。接收端临时生成证书，连接端仅信任配对码中固定的 SHA-256 证书指纹，不安装系统信任证书，不无条件忽略证书错误。配对密钥只在完成证书验证后的加密通道中发送。

配对码是 `sn1:` + 标准 Base64 编码的 UTF-8 JSON：

```json
{
  "protocol": 1,
  "address": "192.168.1.10",
  "port": 47831,
  "key": "<64 位十六进制，256 位随机配对密钥>",
  "fingerprint": "<64 位十六进制，证书 DER 的 SHA-256>",
  "expiresAt": "2026-11-21T12:10:00+00:00"
}
```

只接受私有、回环或链路本地 IPv4，不通过 DNS 寻找设备。配对信息不持久化，停止接收后失效。

TLS 内消息为**四字节大端正整数长度 + UTF-8 JSON**，每帧最多 2 MiB，JSON 最大深度 96。最多四条并发连接，接收端单次请求（含用户确认）约 55 秒超时，客户端约 60 秒超时。

读取请求：

```json
{"protocol":1,"key":"<配对密钥>","operation":"read"}
```

写入请求：

```json
{"protocol":1,"key":"<配对密钥>","operation":"write","expectedVersion":"<上次读取的版本>","data":{"notes":[],"taskLists":[]}}
```

成功响应：

```json
{"status":"ok","snapshot":{"version":"<目标设备的新版本>","data":{"notes":[],"taskLists":[]}}}
```

拒绝响应：

```json
{"status":"rejected","message":"接收设备的数据已变化，请重新读取后再同步。"}
```

状态为 `ok`、`unauthorized`、`invalid`、`rejected` 或 `error`。只有 `ok` 确认完成，响应丢失后应重新读取。写入成功应返回实际保存的快照，让发送端核对内容。

## 手机端预留

JSON 使用 camelCase，完整字段见 `Shared/Contracts.cs` 和 `Shared/Models/` 中的模型；GUID 为字符串、日期为 ISO 8601。手机端应保留未编辑的字段，防止清除电脑端样式。背景图片路径必须为空，坐标尺寸作为兼容字段保留，不作为跨设备布局。

约束为最多 2000 张便签/清单、10000 个任务、16 层子任务，合法颜色、字体大小和透明度，标识不能重复。`TaskItem.subItems` 递归表达子任务，`isDone` 表示完成状态，展开状态不持久化。

手机端可先实现配对码输入、TLS 指纹验证、读写协议和本地快照存储；扫码可复用配对码。服务器连接复用 [HTTP 接口](../Server/README.md)。具体手机平台、账号界面、后台同步、扫码均待手机端阶段实现。

实现参考：[SslStream](https://learn.microsoft.com/dotnet/api/system.net.security.sslstream)、[证书验证回调](https://learn.microsoft.com/dotnet/api/system.net.security.remotecertificatevalidationcallback)。
